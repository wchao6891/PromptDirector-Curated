# 游戏实机的操作与反馈

为游戏概念视频写清“玩家做了什么、系统怎样回应”。适用玩法演示、游戏感短片与概念预演；不能把生成视频声称为真实可玩版本或实际游戏录屏。

## 先确定要证明哪种玩法
一句话写玩家目标和核心操作。例如潜行到达目的地、利用水流打开出口、通过弱点击破护盾。美术风格和HUD不能代替机制。

确认表现模式：连续可操控视角、允许短暂脚本镜头的实机演示、或剪辑预告。不要默认强制全程一个视角，也不能在核心操作发生时切走，只展示结果。

## 用因果表构造过程
每个事件写：触发条件 → 玩家动作 → 世界或敌人变化 → 可见反馈 → 留给下一步的状态。

C063 的潜行建立警戒、隐藏、脱离警戒；C159 用机关激活触发守卫、弱点命中触发血条减少。能删掉HUD仍读懂主要动作，再加最必要的界面反馈。

界面分两类：血量、目标等固定在屏幕；警戒标识或交互提示可绑定世界对象。不要把所有元素锁在屏角，也不要让屏幕HUD随墙面透视歪斜。只加入本次机制需要的项目，直播聊天栏、延迟数值不自动附送。

视角变更要有玩家操作或叙事理由：开镜由举起武器触发，退镜回到同一位置与方向。脚本镜头结束后回到可辨的操控位置。镜头绕身不自动改变角色的朝向。

## 状态与数值
建立最小状态账：目标数、已完成数、当前道具、警戒/机关阶段；需要弹药或生命值时才加。一次动作改变哪些值要对应，不能预先显示完成。C219 原词有多阶段目标和固定数字，实际计数未自然闭合；只学习模式切换，迁移时重新推导目标数量。

如果提示词中写数值，必须与本次事件相符。不能直接复制来源的HP、分数或弹药。需精准品牌字、计数或UI排版时，区分生成的画面与后期确定性叠加；用户只要生成提示词时可表达意图，但不保证模型逐字正确，也不默认要求所有HUD后期做。

## 迁移示例（本包新写）
```text
第三人称潜行概念演示。玩家目标是拿到仓库门卡并打开出口。场地只有货架通道、值班桌和出口，三者连续相连。
角色绕到货架后，巡逻员视线扫过外侧，警戒条升到怀疑；角色停止移动藏于货架，巡逻员离开后警戒回落。
玩家接近值班桌时才出现拿取提示。手接触门卡并将其收起后，物品栏才显示门卡。
角色沿已见通道到出口，将门卡贴读卡器；绿灯亮、门锁打开后，目标才由“找到门卡”切换为“离开仓库”。镜头保持跟随玩家，不用完成字样替代开门动作。
```

## 交付与检查
输出目标、关键事件因果表及成片提示词。核对切镜/开镜前后位置、道具归属、目标计数、UI触发时刻与动作接续。避免“击中之前掉血”“未拿道具已出现物品栏”“任务完成但出口仍锁着”。

用户要求真实产品广告时保留“概念演示”属性，不能让这个Skill替代游戏开发或真实录制。
